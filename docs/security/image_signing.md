# Image Signing And SBOM

MiroConsumer container images are signed with cosign after they are pushed to
GHCR. The signing job stores signatures in the image registry manifest so a
deployment host can verify integrity before starting the containers.

## CI Signing

The `.github/workflows/image-sign.yml` workflow installs cosign, signs the
backend, worker, frontend, and monolith images, then runs `cosign verify` against
each pushed image.

Required GitHub Secrets:

- `COSIGN_PRIVATE_KEY`: private signing key generated by `cosign generate-key-pair`
- `COSIGN_PASSWORD`: password for decrypting the private key
- `COSIGN_PUBLIC_KEY`: public key used by CI and deployment verification

Store `COSIGN_PRIVATE_KEY` and `COSIGN_PASSWORD` only in GitHub Secrets or a
cloud KMS-backed secret store. Publish the public key as `ops/cosign.pub` or set
`COSIGN_PUBLIC_KEY` in the deployment environment.

## SBOM

The Docker image workflow generates an SPDX JSON SBOM as `sbom.spdx.json` using
Trivy and uploads it as a release artifact. Keep the SBOM with the corresponding
image tag so incident response can trace exact dependencies.

## Deployment Verification

Before production rollout, run:

```bash
COSIGN_PUBLIC_KEY_PATH=ops/cosign.pub ops/verify-image-signature.sh ghcr.io/OWNER/miroconsumer-backend:latest
```

`docker-compose.prod.yml` also includes the `image-signature-verify` profile. It
runs `cosign verify` for the backend, worker, and frontend images before deploy.

unsigned or tampered images are rejected: the verification script exits non-zero
and prints `Unsigned image rejected` when cosign or the public key is missing, or
when `cosign verify` fails.
